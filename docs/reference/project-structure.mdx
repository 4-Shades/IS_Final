---
title: "Project structure"
description: "What each directory and top-level file in the repository contains."
---

```text
IS_Final/
├── .github/workflows/ci.yml   Tests and lint on every push and PR; ECR image push on main
├── agents/
│   ├── host_agent/            Receives trip requests and calls the other three agents
│   ├── flight_agent/          Suggests flights
│   ├── stay_agent/            Suggests accommodation
│   └── activities_agent/      Suggests activities
├── common/
│   ├── a2a_server.py          Builds each agent's FastAPI app, including the API-key check
│   ├── a2a_client.py          The Host's HTTP client for calling agents
│   ├── llm.py                 Ollama and OpenAI clients, structured output, LLM metrics
│   ├── rag/                   Retrieval (see Component design for each file's role)
│   │   ├── wikivoyage.py      Fetch articles and split them into sections
│   │   ├── ingest.py          Build the index: python -m common.rag.ingest
│   │   ├── store.py           Agent sections, embedding model and identity, store selection
│   │   ├── chroma_store.py    Chroma vector store (self-hosted)
│   │   ├── simple_store.py    LlamaIndex file store, read-only at query time (Vercel)
│   │   ├── retrieve.py        Look up guidance for a prompt; never fails a request
│   │   └── types.py           Guidance result type, importable without LlamaIndex
│   ├── telemetry.py           Optional metrics export over OTLP
│   ├── travel_data.py         Geocoding, places, and weather adapters (not yet used by agents)
│   └── serve.py               Container entry point; starts the agent named by APP_MODULE
├── shared/
│   ├── config.py              Reads every environment variable
│   └── schemas.py             Request and response models shared by all services
├── tests/                     pytest suite; no external services needed
├── infra/
│   ├── aws/foundation/        Terraform: network, IAM, ECR, log bucket, CI role
│   ├── aws/ecs-agents/        Terraform: ECS services, load balancer, WAF, schedules
│   ├── grafana/               Importable Grafana dashboard
│   ├── ollama/Dockerfile      Ollama image for hosting it on another server
│   └── kubernetes/            Kubernetes manifest for Ollama
├── data/rag/destinations.txt  Destinations to ingest
├── data/rag/vercel/          The Vercel index, committed (the local index and cache under data/rag/ are gitignored)
├── docs/                      This documentation (Mintlify)
├── requirements/
│   ├── api-core.txt           Agent dependencies without retrieval (what Vercel installs)
│   ├── api.txt                api-core.txt plus the retrieval packages
│   ├── api-vercel.txt         api-core.txt plus LlamaIndex and OpenAI embeddings, without Chroma (Vercel agents)
│   ├── ui.txt                 UI dependencies
│   └── dev.txt                Both, plus pytest and ruff
├── requirements.txt           Streamlit Cloud entry point; installs requirements/ui.txt
├── Dockerfile                 Two images: api-runtime (default, agents) and ui-runtime
├── compose.yaml               Runs Ollama, the agents, and the UI locally; the ingest profile builds the index
├── vercel.json                Vercel Services: the four agents, with only the Host public
├── .vercelignore              Keeps secrets, infra, docs, tests, and the UI out of Vercel uploads
├── run.py                     Starts the four agents and the UI without Docker
├── travel_ui.py               Streamlit UI
├── .env.example               Template for .env
└── pyproject.toml             pytest and ruff settings
```

Each agent directory has an `agent.py` with the prompt and model call (except the Host), a `task_manager.py` that handles `/run`, an `__main__.py` that builds the app, and a `.well-known/agent.json` with the agent's name and description.
